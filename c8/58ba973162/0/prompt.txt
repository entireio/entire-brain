I pushed this into a local branch: model-adaptive-brain.

The main change is that I moved the adaptation into the benchmark/context protocol rather than the core brain engine. Validation commands and scoring are unchanged.

The original approach. more brain context, helped some models but hurt others by causing extra searching and token usage. The new version is model-adaptive: compact packets + stop rules for stronger models, checklist-style packets for smaller models.

Results

• GPT-5.5

Original: 94 → 95, slower, +57% tokens
Change: compact packet, no forced brain brief
New: 83 → 95, 157s → 90s, 515k → 318k tokens

• GPT-5.4-mini

Original: 92 → 95
Change: standard checklist packet
New: still brain-positive

• Claude Opus

Original: 96 → 91
Change: compact XML packet + stop/validation rules
New: 88 → 93, 89s → 79s, 567k → 492k tokens

• Claude Sonnet

Original: 95 → 92, slower, more tokens
Change: compact XML packet + validation reporting
New: 93 → 93, 118s → 49s, 1.37M → 659k tokens

• Claude Haiku

Original: 86 → 92
Change: standard checklist packet
New: still the strongest brain-positive signal

The takeaway seems to be that stronger models benefit from compact repo memory with stricter stopping rules, while smaller models benefit from more explicit checklist-style guidance.

  Verdict: the detector is a solid, safe, well-tested artifact — but it is NOT ready to
  be presented as proven, because the A/B that justifies it is circular and the "0 
  false alarms" claim is degenerate. Fix the eval, not the engine.

  ✅ What's genuinely solid (verified)

  - Engine design is sound and narrow: two high-precision shapes
  (operand-survives/id-swapped changed; assignment-absent-everywhere deleted, opt-in).
  Real precision guards: comment-skip, test-skip, global-presence check,
  locus-prioritized ordering, confidence scoring.
  - Read-only & safe: no writes; RE2 regexes (no ReDoS); path-traversal guard is sound
  — I tested it independently: a/../../etc/passwd, foo/../../../etc/passwd, absolute
  paths all blocked or contained, zero escapes.
  - Tests are real, not tautological: 4/4 pass, including a genuine clean-tree negative
  (exercises the presence guard) and the opt-in-deletion test. Determinism/UTF-8/CRLF
  handling verified safe.

  🔴 Blocking problem: the eval can't honestly demonstrate the benefit

  1. The A/B is circular (CRITICAL, verified). run.py:1580 tells the agent: "…restore 
  expected exactly in place of current," and mcp.go:261 returns
  file/line/expected/current. The harness computes the fix and the agent pastes it —
  this measures transcription, not detection. (In fairness: the arm is explicitly
  Experimental, env-gated A/B (default OFF) with honest comments — the danger is only
  if its pass-rate lift gets surfaced as a "radar win." Finding #8: nothing flags it as
  answer-assisted in the report.)
  2. "0 false alarms" is degenerate (CRITICAL, verified). regression_eval.py:62 =
  len(clean) on the same 2 tuned tasks, against a tree that still holds the invariant —
  the guard suppresses by construction. It's not a precision measurement; it can't
  return non-zero.
  3. Unproven marginal value. The detector reads expected straight from history that
  already contains the answer — so its value over a plain brain_history grep is
  currently unmeasured. Needs a brain_history-only control arm.

  ⚠️  The "precise / 0 false alarms" claim breaks on routine cases

  (:398-419) — factually false output (bounded: off over MCP, but the eval passes
  --include-deletions).
  - Silent recall holes: literal embedding the id (foo+"foobar"), all-lowercase
  identifiers never extracted, 41+ char literals dropped by the {2,40} cap.

## WS3 — Token-aware refresh daemon: `entire brain watch`

Greenfield, but built entirely as an orchestration loop over existing functions. The
token-frugality is structural: **deterministic refresh is free; agent steps are gated.**

**New command** `internal/cli/watch.go` (+ `watch_test.go`), registered in `root.go`
under the `create` group next to refresh (`root.go:85`).

**Loop behavior** (per tick, default `--interval 5m`; `--once` for a single pass):
1. **Detect change cheaply (no tokens):** compare the checkpoint ref
   (`refs/heads/entire/checkpoints/v1`) HEAD and the `.entire/` session-dir mtime against a
   persisted cursor; also reuse `semanticRefreshNeeded` (`refresh.go:404`) /
   `stale`. If nothing changed, sleep.
2. **Deterministic refresh (no agent tokens):** run refresh with `--agent none --semantic
   --history-index` — keeps semantic + history index fresh for free. Reuse `runRefresh`
   by constructing `newRefreshCommand(opts)` with `SetArgs([... "--agent","none"])` and a
   buffered output (cleanest reuse of existing flag defaults), or call `runRefresh`
   directly with a populated `refreshCommandOptions`.
3. **Token-spending steps, gated:** seed synthesis and `distill` run only when (a)
   explicitly enabled (`--distill`, `--seed-agent` default `none`), AND (b) the
   min-interval since the last token spend has elapsed (`--distill-every`, default 24h),
   AND (c) under the cheap model from **WS1** (`--model`/`--effort`, default to a cheap
   model). Reuse `runDistill` (`distill_cmd.go:106`).
4. **Persist a cursor** at `ENTIRE_PLUGIN_STATE_DIR/repos/<repo-key>/watch.json` recording
   last-deterministic-refresh ref/mtime and last-distill timestamp, so a restart never
   re-spends tokens. Repo-key + state dir come from `repoStoragePaths` (used in
   `distill_cmd.go:114`).

**Trigger mechanism:** start with **polling** (zero new deps) — note fsnotify as a
later enhancement in the doc but don't add the dependency now.

**Flags:** `--interval`, `--once`, `--distill` (default off), `--distill-every`,
`--seed-agent` (default `none`), `--model`, `--effort`, `--budget` (optional cap that
stops further agent calls this run).

README: add a "Keep the brain fresh automatically" subsection under "Create Or Refresh A
Brain" (README.md:33) explaining the free-vs-token split and the cheap-model default.
