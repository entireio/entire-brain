### Issues

#### Critical

#### Important
1. **Daemon never pulls teammates' facts on an idle repo** — `internal/cli/watch.go:~288` (the `!changed` → "no change; nothing to do" early return) runs before the `factsSync` step at `watch.go:~330`. Failure scenario: machine B connects, its user stops producing local changes; the fingerprint never moves, every tick returns early, and teammates' facts never arrive via the daemon — the pull half's main purpose. The consolidation-deferral return also skips the step, so during active work sync runs at the 30m consolidation cadence, not 15m. This matches the plan's letter ("after a successful refresh"), so it may be an intentional ruling — but a reasonable user of "auto-sync" expects an idle machine to receive team memories. Fix: run the throttled `factsSync` check before the `!changed` early return (still skipping it when a changed tick's refresh failed).

2. **Client-claimed author beats server-stamped attribution** — `internal/cli/hosted_sync.go:79-85` stamps `authors[id]` only when the blob record's `Author` is empty, and `factmerge/dedup.go:49-53` never overwrites a stored author. `SanitizeForEgress` (factsync/egress.go) does not clear `Author`, so published blobs carry client-written author values, and those permanently win over the server's `authors` map. The spec's locked decision is "statement-level attribution, server-stamped … never from client-claimed identity." Failure scenario: a buggy or malicious client publishes forged `Author` values and every teammate displays them forever; a server-side handle correction can never propagate. Display-only, but it's a spec deviation at a trust boundary. Fix: prefer `authors[id]` over the blob value when the map has an entry, and clear `Author` in `SanitizeForEgress` so the server map is the only attribution source.

#### Minor
3. `looksLikeJWT` + last-line heuristic (`internal/cli/hosted_token.go:26-29`): a post-token banner line with two dots and no spaces (e.g. `v1.2.3`) would be taken as the token, causing silent per-sync 401s a daemon user never sees. Plan-dictated heuristic; noting the ceiling.
4. "Default branch" is hardcoded `main` (`distillDefaultBranch`, used in hook_cmd.go `syncBranches` and watch.go `factsSync`): repos whose default is `master`/`trunk` never get default-branch coverage, and every repo gets a spurious `main` per-branch marker attempt. Pre-existing repo convention.
5. `readHostedRepoBinding` (hosted_binding.go:33-43) does not strip a `/api/v1` suffix — only connect does. A hand-edited or pre-ce340aec `hosted.json` 404s every sync with only a stderr note. One `TrimSuffix` on read would harden it.
6. `TestSessionEndHookWithoutBindingMakesNoRequests` (hook_hosted_test.go:829-839) never starts the fake server, so `requestCount() == 0` is vacuous.
7. `connect` under `ENTIRE_BRAIN_NO_EGRESS` prints "connected" and silently skips the initial pull (connect_cmd.go:422-425 → hosted_sync.go:31-33). One stderr line ("connected; initial pull skipped: NO_EGRESS") would prevent a false "I'm synced" impression.
