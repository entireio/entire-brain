**2. Env var value formats** (`cellUpstreams`, topology.go:85-109; `NewUpstream`, config.go:278-296):
- `*_SPEC_URL` — full `http(s)://` URL to the service's OpenAPI document (or an HTML docs page, one hop auto-resolved). Must have http/https scheme + host or startup fails. The *proxy base* is derived by stripping the last path segment (`deriveBaseURL`, config.go:301) unless overridden.
- `*_INTERNAL_URL` — optional override for the proxy destination only (e.g. `https://peregrine.search.svc.cluster.local:8080`), so the spec can be fetched from a public host while traffic goes over the internal listener (see config.go:27-34). Empty/unset → base derived from the spec URL.
- Real-world shapes from `config_test.go:292-293` and `:329`: `https://peregrine.us-east-2.entire.internal/openapi.yaml` + `https://peregrine.search.svc.cluster.local:8080`; `http://entire-search-query.entire-search.svc.cluster.local/openapi.yaml`.

**3. Required vs optional.** `Required: true` → missing `SpecURLEnv` is a hard startup error (`cell service %q: %s is required`, topology.go:91). `Required: false` → the upstream is silently skipped when its env is unset, so the same binary rolls to a cell before the backend exists. Required also gates pod readiness: `Upstream.Required` (config.go:74-81) feeds `Store.AllReady`, and a DOWN optional upstream degrades only its own routes without pulling the pod out of rotation. **A new service should ship `Required: false`** and only be promoted later.

**4. PathPrefix.** Merge prepends it to every path key (`internal/gateway/merge/paths.go:50`, `pathStr := spec.Base.PathPrefix + localPath`) and the proxy strips it back before joining BaseURL (`internal/gateway/proxy/proxy.go:83-94`, `http.StripPrefix(up.PathPrefix, rp)`) — the backend still serves bare paths. It also becomes the fallback OpenAPI tag for untagged operations (`paths.go:199-214`), so the prefix is public vocabulary, not a codename. A path published by two upstreams is a hard merge error that pins the gateway to last-good, so the prefix must be unique (topology.go:61-71 documents the TRAILS_SPEC_URL incident).

**5. Spec fetch + merge lifecycle.** `internal/gateway/upstream/fetch.go:39-64` — spec fetches refuse all redirects (SSRF bound); `upstream/store.go` does `Refresh` → `Candidates` → `Commit`/`MarkRejected` with last-good retention; `internal/gateway/server/server.go:239` rebuilds the chi router on change. `InitialLoad` retries until every *required* service is ready or `STARTUP_READY_TIMEOUT` (default 60s) elapses, then binds not-ready rather than crash-looping. The spec's own `servers[]` is deliberately ignored for routing (config.go:22-25). mTLS-only operations are dropped from the merged doc (`merge/mtls.go:87`), so a brainstore spec that marks an op `type: mutualTLS` is excluded from the public surface automatically.

**6. How the gateway reaches upstreams: one shared transport, workload mTLS when configured.** There is no per-upstream `TransportForUpstream` in this repo. `internal/server/api.go:111-128`:

