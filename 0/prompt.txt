**2. `scripts/get-brain.sh` ~lines 79-108 (the `api_get` awk step and `api_rate_limited`): the classification is more precise than the situation needs.**
- **What's there:** An awk pass rewrites the header file to keep only the last response after redirects. A grep then looks for `remaining: 0`, any `retry-after`, or "rate limit" / "abuse detection" in the body, so that a 403 can be told apart from a rate-limited 403.
- **Simpler alternative:** This is an unauthenticated GET of a public repo's releases. Here a non-rate-limit 403 is close to impossible: a private or missing repo returns 404. - **Cost:** The redirect-block handling and the `IgnoresRedirectHeaders` / `HeadersAllowTabs` tests guard a "plain 403 with misleading redirect headers" case that is extremely unlikely against api.github.com. **3. Design: the root cause is untouched, and the deferral is only partly justified.**

- **Why the deferral is partly fair:** `/releases/latest` skips prereleases, so a redirect alone can't resolve `--nightly`.
