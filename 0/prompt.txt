<result>I found three efficiency findings in the diff. The first two have real cost; the third is minor.

**1. The session-level check no longer filters anything** (`internal/cli/pattern_corpus_enrich.go:321`, called once per new or changed session from `internal/cli/pattern_corpus.go:414`)
- **Summary:** `codexSessionRoot` used to stop early unless the transcript contained `"FileChange"`. Now it stops only if the transcript contains no FileChange spelling in any case, no `\u`, and no U+0130. Almost every real transcript contains `\u` somewhere, for example ANSI `\u001b` in Bash tool output, Go's `\u003c`/`\u003e`/`\u0026`, or escaped non-ASCII text. So the check effectively passes every session that has `FilesTouched`, including Claude Code, pi and other non-codex sessions that can never have a FileChange root.
- **Cost:** `codexFileChangePaths` now runs on nearly every new or changed session. Every line it lets through (finding 2) is fully decoded with `decodeTranscriptRecord`, and the result is thrown away for non-codex sessions. Before, this function did nothing for them. Unchanged sessions are skipped by `corpusSessionUnchanged`, so this only hits new or changed sessions. But a full rebuild, or the `IndexerVersion` bump this kind of change usually needs, hits all of them.
- **Cheaper alternative:** Use `s.Agent`, which `bmanifest.Session` already has (`internal/cli/internal/manifest/manifest.go:89`). Skip `codexSessionRoot` unless the agent is codex, or empty for older manifests. Otherwise keep the case-insensitive name check as the file-level filter and apply the `\u`/U+0130 allowance only per line.

**2. The per-line filter lets through every line with an escape, so those lines are decoded twice** (`internal/cli/pattern_corpus_enrich.go:368-372`)
- **Summary:** Inside `codexFileChangePaths`, `mayHoldFileChange(line)` passes any line containing `\u`, which in practice is most tool_result lines and many assistant lines. Each of those is fully decoded with `decodeTranscriptRecord`. Then `corpusEpisodeOps` decodes the same lines again, segment by segment, from `seg.WorkText` (`pattern_corpus.go:423`).
- **Cost:** About 2x the JSON decoding for every line with an escape, and these are usually the biggest lines. That is close to doubling the decode work of corpus build per session, since `corpusEpisodeOps` already decodes every work-text line that starts with `{`. Before, the extra pass decoded only the few lines with a literal `"FileChange"`.
- **Cheaper alternative:** Decode once. Have the episode pass collect the absolute FileChange refs (from `fileChangeRefs`) along with the tool and command ops, compute the root from those paths, and only then apply `repoRelativePath`. A smaller fix: only pass `\u` lines that also contain `"tool_use"` or `"name"`. A FileChange tool name can only appear in a tool block, so this keeps the correctness the PR added and drops tool_result and text lines.

**3. Slow regex runs first, then scans the transcript a second time** (`internal/cli/pattern_corpus_enrich.go:226, 236`)
- **Summary:** `fileChangeNamePattern` is `(?i)filechange`. Because it is case-insensitive, Go's regexp can't use its fast literal-prefix search, so `MatchString` scans byte by byte. It is the first test in `mayHoldFileChange`, so it runs over the whole transcript (line 321) and then again over every line (line 369). That is two regex scans of the full content per session, where before there were two `strings.Contains` scans.
- **Cost:** The regex is usually much slower per byte than `strings.Contains` on multi-MB transcripts. This is small next to the decoding in findings 1 and 2, but it is pure overhead.
