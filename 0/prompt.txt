### Issues

#### Critical (Must Fix)

None.

#### Important (Should Fix)

1. **Raw mode still writes to the brain store at end of run — plan pinned "no store writes"**
   - File: internal/cli/distill_cmd.go:1572-1630 (final `withBrainWriteLock` block, unchanged by the diff)
   - `--raw-facts-out` skips staging, reconcile, and fingerprint *additions*, but the unconditional end-of-run block still runs: `flushFactStoresLocked(true)` → `saveDistillCache(brainDir, newCache)`, `writeFactTaxonomy`, and `manifest.Sources.Facts` overwrite. On a real (non-sandboxed) store, `newCache` under `final=true` is written **without** the prevCache merge, and raw-processed sessions get no entry — so a raw run drops the fingerprints of every session it processed (next production run re-pays their extraction) and stamps the production manifest's facts-source stats with the eval variant's agent/model/warnings. No fact loss (dirtyBranches stays empty), and the shipped harness always sandboxes, but the flag lives on the production `distill` command and is one manual invocation away.
   - Related: raw mode still honors prevCache hits, so `--raw-facts-out` on an already-distilled store silently emits an *empty* raw file. Fine for the sandbox (always fresh), surprising for direct use.
   - Fix: in raw mode, return before the final write block (build `source` without persisting), or at minimum skip `saveDistillCache` and the manifest update.

2. **`--golden-only` runs are indistinguishable in run.json; score/compare silently mis-score them**
   - File: internal/cli/facts_distill_eval_run.go (run command; `distillEvalRunMeta` has no golden-only marker), facts_distill_eval_score.go:2946-2963
   - A `--golden-only` run carries the full corpus's `CorpusSHA256`. `score --corpus` emits every corpus session, so the ~48 never-distilled sessions score as legitimate zero-fact sessions, and `compare` against a full run passes the corpus guard and produces a confidently wrong "golden-only variant wins facts/tokens/agent_calls on every pair" result. Zero-fact-as-valid is the design's core invariant, which makes this failure mode invisible.
   - Fix: record `golden_only` (or the distilled session set) in run.json; have score restrict to it and stamp the summary, and have compare refuse mixed coverage without an explicit flag.

3. **Partial agent failures silently depress a variant's volume/cost scores**
   - Files: internal/cli/distill_cmd.go (agent failure path writes no chunk line; exit is non-zero only when *all* calls fail), facts_distill_eval_run.go:2440 (harness only checks child exit), facts_distill_eval_score.go
   - A variant whose agent flakes on some chunks exits 0 with warnings the harness discards (`CombinedOutput` ignored on success). Score sees fewer chunk/fact lines and reads the variant as cheaper and quieter — the exact headline metrics. The data to detect this exists (`chunk_count` on every chunk line vs. chunk lines seen per session; child summary `FailedChunks`), but nothing checks it.
   - Fix: in score, flag sessions where observed chunk lines &lt; `chunk_count` (or surface `failed_chunks` into run.json) and refuse or annotate the summary.

#### Minor (Nice to Have)

4. **Salt reads raw env, value reads validated env** — distill_cmd.go:2479 uses `os.Getenv(envFactsMaxPerChunk)` while behavior uses `factsMaxPerChunkValue()` (invalid → compiled default). An in-process caller that bypasses `runDistill` validation with an invalid env gets salt "x" but behavior 6. Conservative direction (cache miss, never wrong reuse); unify by salting the validated value.
5. **Duplicate fact ids produce duplicate label-sheet rows** — facts_distill_eval_labels.go:2012-2025 iterates all fact lines; the same id emitted by two chunks appears twice for the owner to label (loader keeps last). Dedupe by id as the judge command already does.
6. **`JudgeConfig` from arbitrary map iteration** — facts_distill_eval_score.go:3080-3083 takes the first entry of a map; a judge file with mixed identities yields a nondeterministic config. Take it from the first *line* or error on mixed configs.
7. **Self-judged runs are not labeled** — spec: "the run summary must label it as such." Summary carries `Variant.Model` and `JudgeConfig` so a reader can notice, but no explicit flag/warning when judge model == distiller model.
8. **Raw-write failure is only a warning** — distill_cmd.go `writeRawEvalLines` warns and drops the rest of the chunk's lines on encode error; the harness treats the run as success and scores a silently truncated file. Rare (local disk), but an eval-validity hole; consider making it fatal in raw mode.
9. **`cap` shadows the builtin** in the run command's flag variable (facts_distill_eval_run.go) — rename to `capPerChunk`.
