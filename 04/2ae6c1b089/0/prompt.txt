  So here's the honest guidance + the prompt most likely to actually benefit.
  
  What makes a prompt benefit from the brain (learned by dogfooding)

  The brain wins decisively when the answer is (a) only in agent session transcripts (not in git messages or committed docs), or (b) the repo is big enough that finding the 
  spot is the cost (brain = fewer tokens/searches). It does not beat a cold agent when the rationale is in committed docs/commit messages (cli has lots of those). And the query
  must contain a strong identifier/keyword, not prose.

  The prompt to ask (most likely to benefit)

  Use a specific, subtle behavior tied to an identifier, phrased as a task, with brain queries that hit:

  ▎ "In entire review, when --base <ref> is passed it must use that explicit base ref end-to-end. Verify the invariant: confirm scopeBaseRef is threaded into both the agent 
  ▎ prompt and the banner, and identify the exact test that guards this. If it's broken, fix it minimally."
  
  Why this one benefits: it's a localization + invariant-recall task in a large file; the brain's search "scopeBaseRef" / inspect history 
  "BaseFlagThreadsThroughToPromptAndBanner" jumps straight to review_context.go + the guarding test, where a cold agent burns tokens grepping. (This is the area the n=3
  benchmark already showed brain-positive.)

  Even stronger (if you want a brain-only-knowledge win): ask about a subtle regression, not documented code:

  ▎ "There's a transcript-path re-resolution subtlety: when the resolver finds a relocated transcript, what must happen to session state, and what bug occurs if it doesn't? 
  ▎ Answer from prior work, then verify in resolve_transcript.go."
