I pushed this into a local branch: model-adaptive-brain.

The main change is that I moved the adaptation into the benchmark/context protocol rather than the core brain engine. Validation commands and scoring are unchanged.

The original approach. more brain context, helped some models but hurt others by causing extra searching and token usage. The new version is model-adaptive: compact packets + stop rules for stronger models, checklist-style packets for smaller models.

Results

• GPT-5.5

Original: 94 → 95, slower, +57% tokens
Change: compact packet, no forced brain brief
New: 83 → 95, 157s → 90s, 515k → 318k tokens

• GPT-5.4-mini

Original: 92 → 95
Change: standard checklist packet
New: still brain-positive

• Claude Opus

Original: 96 → 91
Change: compact XML packet + stop/validation rules
New: 88 → 93, 89s → 79s, 567k → 492k tokens

• Claude Sonnet

Original: 95 → 92, slower, more tokens
Change: compact XML packet + validation reporting
New: 93 → 93, 118s → 49s, 1.37M → 659k tokens

• Claude Haiku

Original: 86 → 92
Change: standard checklist packet
New: still the strongest brain-positive signal

The takeaway seems to be that stronger models benefit from compact repo memory with stricter stopping rules, while smaller models benefit from more explicit checklist-style guidance.

Update: MCP brain, real session data, n=3 👇

Redid this properly with real MCP server delivery this time (actual brain_brief/brain_history calls in the transcripts, not the CLI/sem version), on a repo with real Entire history (Ultron, 128MB .entire). Matched A/B, n=3, same task/model/effort across Claude Haiku/Sonnet/Opus, and validated the Codex side too.

Does the brain beat grep? Yes.

Self-contained-turns (a regression the agent can't solve by searching): no_brain went 0/3 valid, MCP brain went 3/3 across all three models, with 38-72% fewer tokens and 43-61% less time.

Metadata (which the agent already solves): correctness held, but tokens dropped 26-83%, time up to 76%, and the brain even added +5 to +10 on score.

Codex points the same way: n=1 pilots on gpt-5.4-mini and gpt-5.5 (low to xhigh), all +50 to +66, search calls down from 22 to 8.

How it works: disposable worktree per run, apply the regression, baseline is a parentless commit so the agent can't read the answer out of git history. Brain built from Ultron's real sessions (prep timed separately, cached), then hidden validation and scoring (unchanged). Conditions: no_brain / CLI / MCP.

Validity: ran an independent integrity audit. Zero hard flags in the proof set, fairness leak closed (reproduced live), real MCP calls confirmed against the server logs. Also pulled in your PR #1 fix (entire-sem relation drop) with tests, all green.
